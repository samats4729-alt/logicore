# LogiCore — правила для ИИ-агентов в этом репозитории

LogiCore — логистическая платформа **В ПРОДАКШНЕ** (заявки, трекинг, финансы,
документы). Монорепо pnpm: `apps/api` (NestJS + Prisma), `apps/web`
(Next.js 14 + Ant Design + собственный скин), `apps/mobile` (Expo).

## Железные правила (продакшн)

1. Перед КАЖДЫМ `git commit`: `npx tsc --noEmit` в `apps/web`, и в `apps/api`
   если менялся api. Красный tsc = коммитить ЗАПРЕЩЕНО. Без исключений,
   даже для «мелких» правок.
1а. Один коммит = одна страница/одна задача. Не накапливать несколько страниц
   в один коммит.
1б. Не выдумывать вызовы функций/хелперов. Если нужного хелпера нет в кодовой
   базе — оставь код как был. При редизайне форм поля, их типы (Input/Select)
   и правила валидации не менять.
2. При работе над дизайном/вёрсткой ЛОГИКА НЕ ТРОГАЕТСЯ — меняются только
   JSX-разметка и CSS. Обработчики, запросы, стейт остаются как есть.
3. Миграции БД (`prisma/`) — только по явной просьбе пользователя.
4. Не коммитить и не читать вслух `.env` и другие секреты.
5. Общение и отчёты — на русском.

## Работа нескольких агентов в этом репозитории

Над проектом работает несколько сессий-агентов, каждая со своей веткой
(`claude/...`). Владелец пользуется ими **по очереди**, а не одновременно.
Отсюда правила, которые снимают конфликты полностью:

1. **Начинай сессию с `git fetch origin && git checkout -B <своя-ветка> origin/main`.**
   Своя ветка — всегда свежий отросток от `main`, а не продолжение того,
   что осталось с прошлого раза. Иначе две сессии месяцами тянут разные
   истории и потом не сходятся.
2. **Заканчивай работу мержем в `main`.** Ветка живёт один заход. Долгие
   ветки — главный источник конфликтов, потому что соседняя сессия про
   них не знает.
3. **Не трогай чужую ветку** и не переноси из неё коммиты. Если нужное
   лежит в чужой ветке — дождись, пока она попадёт в `main`.
4. **`PRODUCT_AUDIT_PLAN.md` — общий журнал.** Пиши только в конец, не
   переписывай чужие записи: две сессии правят один файл.
5. Перед мержем сверься с `origin/main`: если он ушёл вперёд, сначала
   влей его к себе и прогони проверки заново.

## Мерж в `main` = деплой в продакшн

`main` автоматически раскатывается Railway. GitHub Actions и Railway между
собой **не связаны**: прод уедет даже с красным CI. Поэтому:

- **Изменения без миграции** (код, интерфейс, печатные формы) — агент
  мержит сам, убедившись, что CI зелёный.
- **Изменения с миграцией БД** — сначала бэкап Postgres в Railway, и
  только потом мерж. Бэкап делает владелец: у агента нет доступа к
  консоли Railway. Прямо скажи ему об этом, а не мержи молча.
- **Удаление или переименование таблиц и колонок** — отдельный вопрос
  владельцу каждый раз, даже если он раньше давал общее добро.
  Добавление полей общим добром покрыто.
- Мерж — обычным merge-коммитом, так принято в репозитории.

## Дизайн — обязательно к соблюдению

Перед ЛЮБОЙ работой над интерфейсом сначала прочитай `REDESIGN_PLAN.md` в корне —
это источник правды по дизайну платформы. Краткая выжимка:

### Платформа (кабинеты /company, /admin) — светлый «Apple-стиль»
- Фон страницы `#f4f5f7`, карточки белые, радиус 20–24px, мягкие тени.
- Тёмные акцент-блоки (карты, тикер, featured): глубокий графит `#0b0d12`.
- Акцентный синий `#1677ff`. Шрифт Inter. Суммы — жирные, `tabular-nums`.
- Навигация и фильтры — «пилюли» (активная — чёрная с белым текстом).
- **Новый интерфейс делается на shadcn/ui** (решение владельца от 27.07,
  платформа переезжает на него). Компоненты лежат в
  `apps/web/src/components/ui/`, помощник склейки классов — `@/lib/utils`
  (`cn`). Добавляя новый компонент, бери код с https://ui.shadcn.com и
  клади туда же: shadcn — это не зависимость, а код в проекте.
- Ant Design НЕ выпиливать и старые экраны массово НЕ переписывать: их 100+,
  и разом это не проверить. Переводим страницу на shadcn тогда, когда её и
  так переделываем. До тех пор antd остаётся движком форм/модалок/таблиц и
  перекрывается классами `lc-*` в `apps/web/src/app/globals.css`.
- **`preflight` у Tailwind выключен** (`tailwind.config.ts`) и включать его
  нельзя, пока живы экраны на antd: это глобальный сброс стилей, он разом
  обнулит заголовки, кнопки и поля на всех старых страницах.
- Цвета shadcn заданы токенами в начале `globals.css` теми же значениями,
  что и переменные `--lc-*`. Меняешь палитру — меняй в обоих местах, иначе
  новые экраны станут выглядеть чужими рядом со старыми.
- Других UI-библиотек, кроме antd и shadcn/ui, не добавлять.

### Лендинг (`apps/web/src/app/page.tsx` + `page.module.css`) — тёмный редакционный
- Фон `#030712`, шрифты Unbounded (заголовки) + Inter (текст).
- Фирменные приёмы: индексы секций «(0N — Название)», кинетические заголовки
  с посимвольной анимацией, marquee-строка, гигантский вордмарк в футере,
  кастомный курсор, magnetic-кнопки. Новые секции — строго в этом языке.

### Общее
- Переиспользуй готовые компоненты из `apps/web/src/components/ui/`
  (StatusPill, LiveTicker, FeaturedOrderCard, InteractiveCard, Reveal,
  AnimatedCounter и др.) вместо написания новых аналогов.
- Все шрифты обязаны поддерживать кириллицу.
- Весь пользовательский текст интерфейса — на русском.

## Код

- Страницы `company/orders`, `company/orders/[id]`, `company/users` уже
  перегружены (~2000 строк). НЕ раздувай их дальше: новый UI выноси
  в компоненты, новую логику — в `lib/` или хуки.
- Не плоди `any` — типизируй ответы API через существующие типы в `lib/api`.
- Стили статусов/ролей уже описаны (statusColors, statusLabels, StatusPill) —
  не дублируй, импортируй.

## Команды

- Дев-сервер: `pnpm dev` (api + web) из корня; только веб: `pnpm dev:web`.
- Проверки: `npx tsc --noEmit` в apps/web и apps/api; `pnpm lint`.
- Пакетный менеджер — только pnpm (не npm/yarn).
