# LogiCore — задачи мобильного приложения водителя №1

Задачи для мобильного приложения водителя (`apps/mobile`). Решения
зафиксированы владельцем по обсуждению 9 октября 2026 года. Все пункты — к
реализации; сроки не назначены.

> Это задачи мобильного приложения, не список доработок веб-платформы.
> Правовые основания подключения водителей — отдельный документ:
> [`docs/legal/gph-rental-drivers-kz-2026.md`](../legal/gph-rental-drivers-kz-2026.md).
> Не смешивать одно с другим.

## 1. Регистрация водителя

- [ ] Выбор типа регистрации: физическое лицо или ИП (без требования открыть
      ИП для физлица).
- [ ] Регистрация по номеру телефона с подтверждением кода.
- [ ] Форма персональных данных: имя, фамилия, дата рождения, ИИН, номер
      удостоверения личности, кем выдано (при необходимости — дата выдачи и
      срок действия).
- [ ] Фотографирование удостоверения: лицевая и оборотная стороны. Камера с
      рамкой документа, предпросмотром и кнопкой «Переснять».
- [ ] Запрашивать согласие на обработку необходимых персональных и
      биометрических данных; хранить снимки в закрытом хранилище с
      разграничением доступа.

## 2. Автоматическое подтверждение личности

- [ ] Селфи непосредственно из приложения и проверка присутствия живого
      человека (liveness).
- [ ] Автоматически сравнивать лицо на селфи с фотографией на удостоверении.
      Цель: не заставлять модераторов проверять каждого водителя вручную.
- [ ] При успешной проверке присваивать статус «Личность подтверждена»; при
      неуверенном результате — предложить пересъёмку или отправить на ручную
      проверку.
- [ ] Предусмотреть интеграцию со специализированным SDK/провайдером,
      например Sumsub. **Выбор поставщика и стоимость не утверждены.** Для
      нативного SDK в Expo может потребоваться development build / EAS Build.
- [ ] Понятные статусы проверки: «В процессе», «Подтверждена», «Повторить
      проверку», «Требуется проверка».

## 3. Вкладка «Баланс»

- [ ] Отдельная вкладка «Баланс» в мобильном приложении.
- [ ] Заработок по завершённым перевозкам, доступная сумма, история выплат и
      удержаний, налоги/отчисления, если они применимы к конкретному договору.
- [ ] Корректно показывать состояния «Начислено», «Ожидает выплаты»,
      «Выплачено». **Не обещать доступность вывода**, пока механизм выплат не
      согласован.
- [ ] **Открытый вопрос:** деньги водителю перечисляет парк/диспетчерская
      компания или непосредственно LogiCore? От решения зависит расчёт баланса
      и платёжная логика.

## 4. Съёмка ТТН при закрытии рейса

- [ ] При отправке фото товарно-транспортной накладной открывать
      камеру/сканер документа в приложении.
- [ ] Автоматически оценивать **только качество фотографии**: резкость,
      освещение, блики, целостность документа в кадре, достаточную
      читаемость.
- [ ] Если качество недостаточное — называть причину («Фото размыто»,
      «Документ обрезан», «Слишком темно») и предлагать переснять.
- [ ] Если фото достаточно качественное — разрешать отправку и сохранять файл
      к рейсу на сервере.
- [ ] Предпочесть локальную проверку на устройстве, где это возможно.
      Рассмотреть платформенные сканеры и дополнительную оценку качества.
      Заложить запасной сценарий при ошибочной оценке.
- [ ] **Принятое решение:** НЕ распознавать и НЕ сверять данные ТТН с заявкой
      (номер, дата, маршрут, вес, госномер и т. п.). Проверяется только
      качество снимка.

## 5. Раздел «Мои документы»

- [ ] Перечень загруженных документов водителя и статусы их проверки.
- [ ] Просмотр собственных удостоверения, водительских/автомобильных
      документов и подписанных договоров — при наличии соответствующих
      документов в системе.
- [ ] Доступ к персональным документам — только у самого водителя и
      уполномоченных сотрудников.

## Примечания

- Проверка личности и проверка качества ТТН — две разные функции: первая
  сверяет лица и признаки подмены, вторая только отбраковывает плохие
  фотографии.
- Технические библиотеки, точные алгоритмы и поставщики сервисов выбираются
  при реализации.
