# LogiCore — задачи мобильного приложения водителя №1

Задачи для мобильного приложения водителя (`apps/mobile`). Решения
зафиксированы владельцем по обсуждению 9 октября 2026 года. Все пункты — к
реализации; сроки не назначены.

> Это задачи мобильного приложения, не список доработок веб-платформы.
> Правовые основания подключения водителей — отдельный документ:
> [`docs/legal/gph-rental-drivers-kz-2026.md`](../legal/gph-rental-drivers-kz-2026.md).
> Не смешивать одно с другим.

## Статус на 09.10.2026

Сделано в ветке `driver-app-1` (до водителей дойдёт с новой сборкой
приложения: камера и обработка снимка — новые модули). Решения владельца,
принятые по ходу (09.10):

- поля удостоверения и согласие — **добавить** (новые поля в базе);

- «Баланс» — **платит парк**, как сейчас;
- вход по СМС и проверка лица — **отложены** до выбора платных сервисов.

## 2. Автоматическое подтверждение личности

*Отложено целиком до выбора поставщика (например, Sumsub) и договора с ним.
Пока личность проверяет парк по фото «с удостоверением в руке».*

- [ ] Селфи непосредственно из приложения и проверка присутствия живого
      человека (liveness).
- [ ] Автоматически сравнивать лицо на селфи с фотографией на удостоверении.
      Цель: не заставлять модераторов проверять каждого водителя вручную.
- [ ] При успешной проверке присваивать статус «Личность подтверждена»; при
      неуверенном результате — предложить пересъёмку или отправить на ручную
      проверку.
- [ ] Предусмотреть интеграцию со специализированным SDK/провайдером,
      например Sumsub. **Выбор поставщика и стоимость не утверждены.** Для
      нативного SDK в Expo может потребоваться development build / EAS Build.
- [ ] Понятные статусы проверки: «В процессе», «Подтверждена», «Повторить
      проверку», «Требуется проверка».

## 4. Съёмка ТТН при закрытии рейса

- [x] При отправке фото товарно-транспортной накладной открывать
      камеру/сканер документа в приложении.
- [x] Автоматически оценивать **только качество фотографии**: резкость,
      освещение, блики, целостность документа в кадре, достаточную
      читаемость.
- [x] Если качество недостаточное — называть причину («Фото размыто»,
      «Документ обрезан», «Слишком темно») и предлагать переснять.
- [x] Если фото достаточно качественное — разрешать отправку и сохранять файл
      к рейсу на сервере.
- [x] Предпочесть локальную проверку на устройстве, где это возможно.
      Рассмотреть платформенные сканеры и дополнительную оценку качества.
      Заложить запасной сценарий при ошибочной оценке. *Проверка — на
      телефоне, без сервера (`apps/mobile/lib/photo-quality.ts`); запасной
      сценарий — «Всё равно отправить». Платформенный сканер не ставили: это
      ещё один модуль, а рамка и проверка закрывают задачу.*
- [x] **Принятое решение:** НЕ распознавать и НЕ сверять данные ТТН с заявкой
      (номер, дата, маршрут, вес, госномер и т. п.). Проверяется только
      качество снимка.

## Примечания

- Проверка личности и проверка качества ТТН — две разные функции: первая
  сверяет лица и признаки подмены, вторая только отбраковывает плохие
  фотографии.
- Технические библиотеки, точные алгоритмы и поставщики сервисов выбираются
  при реализации.
