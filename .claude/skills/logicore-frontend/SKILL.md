# Интерфейс LogiCore

## Куда идём

**Цель — полностью убрать Ant Design** (решение владельца, 27.07.2026).
Сосуществование временное, а не целевое состояние.

Масштаб на 27.07: 98 файлов, ~39 900 строк. Тяжёлое — не кнопки:
`Form` (34 файла, своё хранилище и валидация), `Table` (37, сортировка,
страницы, итоги), `Select` (26), `Modal` (28), `DatePicker` (22).

Порядок ухода — от безопасного к рискованному:
1. **Показ**: Typography, Tag, Card, Space, Divider, Empty, Spin. Чистая
   вёрстка, логики нет.
2. ✅ **`message` → sonner** — сделано 27.07. Убрано 538 вызовов в 81
   файле, включая второй способ получения — `App.useApp()`.
3. **Button** — идёт сейчас. Сделаны три экрана заявок (мастер, список,
   карточка): 50 кнопок из 363. Осталось 313 в 76 файлах.
4. **Modal** — по одному экрану.
5. **Select и DatePicker** — нужны свои компоненты (комбобокс с поиском,
   календарь).
6. **Table** — журналы с итогами и страницами, по одному.
7. **Form** — последним. Тут валидация заявок, ставки, НДС: переводить
   форму целиком и прогонять браузерный тест на неё.

Правила на время перехода:
- **Новый экран — только на shadcn.**
- Существующий переводим целиком и с проверкой, а не наполовину.
- Массовая замена «поиском по файлам» запрещена: в antd-компонентах висит
  логика, её нельзя терять под видом вёрстки. Исключение — компоненты без
  логики вроде `message`; там кодмод можно, но результат обязан пройти
  `tsc`, сборку и браузерный тест, а не только взгляд по диагонали.
- Других UI-библиотек, кроме antd и shadcn/ui, не добавлять.

## Кнопки

`Button` из `@/components/ui/button`, иконки — `lucide-react` детьми, а не
пропом `icon`. Соответствие пропов antd:

| antd | shadcn |
|---|---|
| `type="primary"` / без типа | вариант по умолчанию |
| `type="default"` | `variant="outline"` |
| `type="text"` | `variant="ghost"` |
| `type="link"` | `variant="link"` |
| `type="dashed"` | `variant="outline" className="border-dashed"` |
| `danger` | `variant="destructive"` (у ghost/link — `className="text-destructive"`) |
| `size="small"` | `size="sm"` |
| `block` | `className="w-full"` |
| `htmlType="submit"` | `type="submit"` |
| только `icon`, без текста | `size="icon"` + обязательный `aria-label` |

Своего состояния загрузки у shadcn нет. `loading={x}` раскладывается на
`disabled={x}` и `{x ? <Loader2 className="h-4 w-4 animate-spin" /> :
<Иконка className="h-4 w-4" />}`. Обёртку ради этого не заводим: три
строки на месте понятнее лишнего компонента.

**Перед коммитом экрана — поиск по `globals.css` на `.ant-btn`.**
Фирменные правила были завязаны на этот класс (`.lc-cta`, панель
действий, панель фильтров, кнопки мастера). Убираешь antd — селектор
перестаёт совпадать, и кнопка молча теряет вид: разметка на месте,
клик работает, а выглядит как голый текст.

## Уведомления

`toast` из `sonner`, никогда не `message` из antd. `<Toaster />`
смонтирован один раз в `src/app/providers.tsx` — внутри `ThemeProvider`,
чтобы уведомления жили в той же теме, что и остальное приложение.

- `toast.success` / `toast.error` / `toast.warning` / `toast.info`.
- Заменить прошлое уведомление вместо новой стопки: второй аргумент
  `{ id: 'ключ' }` (в antd это было `{ content, key }`).
- Проверка живёт в `e2e/notifications.spec.ts`. Она нужна: без
  смонтированного `<Toaster />` вызов `toast()` молча ничего не делает, и
  ни типы, ни сборка этого не покажут.

## Компоненты

- Добавлять **только через CLI**: `npx shadcn@latest add <имя> --yes`.
  Он ставит зависимости через pnpm и не ломает лок-файл.
- **Базовые компоненты в `src/components/ui/` без необходимости не
  менять.** Своя логика — в отдельный компонент рядом
  (`src/components/orders/…`), а не правкой базового.
- Иконки — `lucide-react`. Иконки antd в новом коде не использовать.

## Правило страницы целиком (решение владельца, 10.08.2026)

**Взялся за страницу — переводи на новый язык всё, что на ней есть.**
Не только тот блок, ради которого пришёл: заголовок, кнопку «Назад»,
переключатель вкладок, кнопки действий в шапке — всё.

Причина простая: половинчатый перевод виден сразу. Новый блок с тёмной
заливкой рядом со старой синей кнопкой и антовскими вкладками читается
как два разных продукта на одном экране, и владелец каждый раз находит
это первым.

Что это значит на практике:

- главное действие заливается тёмным (`--nova-primary`), синий остаётся
  ссылкам и подсветке;
- шапка страницы — `hero` из `components/nova/nova.module.css`: надзаголовок,
  заголовок, подпись, действия справа;
- вкладки — пилюли (`pills`/`pill`/`pillActive` оттуда же), а не
  `Tabs` из antd;
- «Назад» — не круглая иконка из antd, а обычное действие в шапке.

Исключение одно: таблицы и формы внутри страницы остаются на antd, пока до
них не дошла очередь перевода (см. порядок ухода выше). Оболочка страницы
переводится всегда.

## Повторяющийся элемент — один компонент

**То, что встречается на нескольких экранах, живёт одним компонентом.** Не
копией на каждой странице и не «почти таким же» вторым файлом рядом.

Так уже разъехалась плашка статуса: журнал получил вид эталона, а карточка
рейса, поиск и уведомления остались с прежним — один и тот же «Завершён»
выглядел по-разному, и заметил это владелец, а не проверки.

Если новому экрану нужен другой вид того же элемента — это признак не
второго компонента, а либо нового варианта у существующего, либо того, что
старый пора менять везде. Второй файл `ЧтотоPill2` заводить нельзя.

Проверять просто: перед тем как писать компонент, поискать по названию
сущности (`StatusPill`, `Pill`, `Badge`) — возможно, он уже есть.

## Дизайн-язык

- **Фон страниц белый.** Карточки отделяются тенью, а не серым полотном.
- Тени — из `tailwind.config.ts`: `shadow-soft` (обычная карточка),
  `shadow-lift` (приподнятая). Первый слой — волосяная обводка через
  spread, поэтому рамка карточкам не нужна.
- Тема пока **чёрно-белая**. Цвет добавляется точечно и только по просьбе
  владельца. Исключение — приход/расход: зелёный и красный.
- Токены цветов — в начале `globals.css`, теми же значениями, что и
  переменные `--lc-*`. Меняешь палитру — меняй в обоих местах.
- Радиусы: карточка `rounded-2xl`, поле `rounded-xl`, кнопка/пилюля
  `rounded-full`.

## Плотность — отдельное требование владельца

«Всё раздуто, надо чтобы помещалось в один экран». Практически:

- у antd-полей **не ставить `size="large"`** (это 40px вместо 32px);
- `gutter` в сетке — 12, не 24;
- подпись поля 12px, отступ под ней 4px, между полями 10px;
- заголовок раздела 13px, а не 15px.

## Выбор из большого списка — модальное окно, не выпадающий список

Если записи пополняет пользователь (адреса, контрагенты, водители,
машины, товары, заявки), их рано или поздно станут сотни. Выпадающий
список для этого не годится.

Делать окно с: строкой поиска, фильтрами по существу (город, контрагент,
тип), достаточной строкой (чтобы узнать запись, не открывая), частыми
вариантами сверху. Образец — `components/orders/AddressPicker.tsx`.

Выпадающий список оставлять только для заведомо коротких наборов: тип
точки, ставка НДС, форма оплаты.

## Ловушки, на которых уже теряли часы

**1. Preflight у Tailwind выключен** (`corePlugins.preflight: false`) —
иначе разъедутся все экраны на antd. Из-за этого у голых `<button>` и
`<input>` остаются стили браузера: объёмная рамка и серый фон. Сброс уже
есть в `globals.css` в `@layer base` — только фон и рамка, только для
элементов без классов `ant-*`.

Почему именно так: `font: inherit` в сбросе **раздувает верхнюю
навигацию** кабинета, а вне `@layer base` селектор с `:not` оказывается
тяжелее классов Tailwind и перебивает их.

**2. Мини-сброс вместо preflight обязан быть в `:where()`.** Селектор
`button:not([class*='ant-'])` весит (0,1,1) — больше, чем утилита
`.bg-primary` весом (0,1,0), и обнуляет кнопкам shadcn фон и рамку.
`@layer base` не спасает: у Tailwind это порядок сборки, а не каскадные
слои CSS, и решает вес. Поломка невидима для `tsc` и сборки — кнопка
есть, нажимается, но белая на белом. Ловится `e2e/buttons.spec.ts`.

**3. Не запускать `next build`, пока работает dev-сервер.** Сборка стирает
`.next`, дев-сервер начинает отдавать 404 на свои чанки, страница не
оживает — кнопки молча перестают работать. Выглядит как поломка
приложения, ломается только стенд. Лечится `rm -rf .next` и чистым
перезапуском.

**4. Сборочные пакеты — в `dependencies`, не в `devDependencies`.**
Railway ставит зависимости с `NODE_ENV=production` и devDependencies
пропускает. Так уже падал прод на `Cannot find module 'tailwindcss'`. CI
этого не ловит: там ставится всё.

## Проверка — обязательна

Работа над интерфейсом не считается сделанной без прогона:

```
pnpm --filter web e2e        # против поднятых API и веба
```

Тесты в `apps/web/e2e`. Поменял компонент — приведи сценарий в
соответствие, это не формальность: именно так ловятся поломки.

Проверять надо **вычисленный стиль**, а не разметку: у сломанной кнопки
разметка правильная. Образец — `e2e/buttons.spec.ts`.

Ловушки браузерных тестов, уже найденные:
- antd переиспользует разметку выпадающего списка — брать только видимые
  пункты (`.ant-select-item-option:visible`);
- шаги мастера заявки отрисованы разом, общий селектор ловит скрытые поля
  других шагов — целиться в конкретный `id`;
- после выбора адреса подпись кнопки меняется, «второй» элемент перестаёт
  быть вторым — каждый раз брать первый незаполненный.

## Что нельзя

- Менять логику под видом вёрстки. При работе над дизайном меняются
  только разметка и стили: обработчики, запросы, валидация и расчёты
  остаются как есть.
- Трогать публичную страницу отчёта `shared/report/[token]` «заодно»: у
  неё свой светлый вид, тёмная тема кабинета на неё не распространяется.
